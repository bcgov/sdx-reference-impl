Current project goal:
Implement the initial SDX Reference Implementation Resource Server using a Widgets API, following the existing bcgov/quickstart-openshift NestJS/PostgreSQL/Prisma/OpenShift template conventions.

Current state:
- Backend is NestJS with Prisma 7 and PostgreSQL/Flyway.
- Static OpenAPI contract exists at `backend/openapi/widgets.openapi.yaml`.
- Spectral config exists at `backend/.spectral.yaml` and points at:
  `https://raw.githubusercontent.com/bcgov/csit-api-governance-spectral-style-guide/refs/heads/main/dist/spectral/strict-ruleset.yaml`
- Widgets API implementation exists under `backend/src/widgets/`.
- Auth helpers exist under `backend/src/auth/`.
- Global error filter exists at `backend/src/common/http-exception.filter.ts` and is registered in `backend/src/app.module.ts`.
- Widget create/update/patch service methods validate runtime input types, string sizes, enum values, UUID path params, and JSON-compatible metadata before calling Prisma.
- Widget create supports optional `Idempotency-Key` header on both user and admin create operations. Reusing the key with the same request body returns the original created widget; reusing it with a different body returns `409 Conflict`.
- Single-widget create, get, replace, and patch responses return an `ETag` header derived from widget `id` and `updatedAt`. User and admin replace, patch, and delete operations accept optional `If-Match`; stale values return `412 Precondition Failed`.
- Widget validation now distinguishes malformed requests (`400 Bad Request`) from semantic Widget validation failures (`422 Unprocessable Entity`). Both use BCGov Problem Details; non-validation errors use BCGov ErrorResponse.
- OpenAPI documents `409 Conflict` for write conflicts, `429 Too Many Requests` with `Retry-After`, and `500 Internal Server Error` with a correlation ID. The global error filter preserves inbound `x-request-id` or `x-correlation-id`; when this API generates a value, it uses `widget-<uuid>`.
- Static OpenAPI includes operation-level named request/response examples for Widget create, replace, patch, list, get, and reusable error responses.
- Generated OpenAPI can be refreshed with `cd backend && npm run generate:openapi`. The export script starts the built Nest app on a temporary local port, fetches `/api/docs-json`, and writes both `backend/openapi/widgets.generated.openapi.json` and `backend/openapi/widgets.generated.openapi.yaml`. `alignGeneratedWidgetSpec()` normalizes path/component/key ordering to make comparison with the static spec easier.
- Prisma widget model exists in `backend/prisma/schema.prisma`.
- The initial Flyway migration is `migrations/sql/V1.0.0__create_widgets.sql` and directly creates the widget and idempotency tables with their final names.
- Simple client exists at `backend/src/client/widgets-client.ts`.
- README has local validation/run/test notes and future SDX TODOs.
